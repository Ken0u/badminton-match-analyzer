# Contact uncertainty at review-window edges

[Issue #295](https://github.com/Ken0u/badminton-match-analyzer/issues/295)
addresses unresolved reference intervals overlapping a complete review window
while their navigation frames lie outside it. Contact uncertainty uses inclusive
native frame bounds; review windows use half-open bounds.

For example, a reviewed contact at navigation frame 9 with possible bounds
`[9, 10]` can occur on the first frame of review window `[10, 20)`. A contact
at frame 20 with possible bounds `[19, 20]` can occur on its final included frame.
The earlier evaluator checked only navigation-frame membership and scored those
windows despite their unresolved timing. The same eligible contact domain fed
recognition scores.

The existing `contact_timing_needs_adjudication` exclusion now applies whenever
an unresolved reviewed/corrected serve or shot interval overlaps the window.
For inclusive contact bounds `[left, right]` and window `[start, end)`, overlap
means `left < end and start <= right`. A last possible contact frame equal to
`start` is included; an interval beginning at `end` is disjoint. Point-adjudicated
contacts, predicted labels and rally endings retain their existing behavior.

The change preserves eligibility-reason precedence, window IDs, explicit skipped
windows, original/excluded input counts and unrelated reliable windows. It does
not choose a contact frame, alter labels, split intervals, change matching or
modify source/clock/camera/candidate-evidence checks. Recognition consumes the
same corrected eligibility domain without a separate production change.
