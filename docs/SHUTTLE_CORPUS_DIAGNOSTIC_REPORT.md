# Frozen published-coordinate shuttle diagnostic

Owning task: [issue 145](https://github.com/Ken0u/badminton-match-analyzer/issues/145), under [localization roadmap 65](https://github.com/Ken0u/badminton-match-analyzer/issues/65). The initial implementation passes software verification; native execution and scoring remain pending. This report will record observed results after the fixed all-source run and sealed scoring; no accuracy improvement is established.

The [source preparation](SHUTTLE_SUPERVISION_REPORT.md) retains 201 published clips, 29 publication groups, 91,579 native frames and 91,214 published rows. Twenty-five incomplete CSV files and all their 12,235 rows remain quarantined; 365 native tail frames have no published row. The other 176 files contain 78,979 structurally aligned rows. These are publisher references, not independently reviewed truth. Training, model deployment, redistribution and independent-test eligibility remain false.

The [fixed protocol](../data/manifests/shuttle_corpus_diagnostic_v1.json) selects the existing TrackNet checkpoint and unchanged application adapter: 512x288 input, 0.5 heatmap threshold, CUDA float16, current automatic camera boundaries and observed component selection. No model variants, training, inpainting, interpolation, default changes or weight installation are in scope. The complete raw output index is sealed before a separate scoring command. Agreement uses the pre-existing 0.005 source-diagonal localization tolerance; wrong locations count as both false detections and misses. Unknown/quarantined rows never become negatives, and unavailable negative outputs never become true negatives.

Every native source frame and raw published row remains explicit in coverage. Visibility is agreement with publisher flags; localization error is conditional on its stated support. Group and publication-partition rollups do not imply original-source disjointness. Component-presence diagnostics assess observed above-threshold components without choosing a different prediction. The published Test namespace is an upstream evaluation source, not a new unseen holdout.

Reproduction requires a repository clone, the pinned ignored source-evidence bundle and corpus from task 143, the original checkpoint, CUDA and a genuine task/resource grant. A clone alone supplies none of those local data artifacts. Pin `BADMINTON_ROOT`, `BADMINTON_DATA_DIR` and `BADMINTON_WEIGHTS_DIR` to the original root, its existing real `data/processed` Store and original `models/weights` before configuration imports. Clear `GH_TOKEN`/`GITHUB_TOKEN` and use offline GitHub configuration for research code. `scripts/diagnose_shuttle_corpus.py run` creates a dedicated ignored output lineage and uses real shared Store admission; temporary timestamp adapters do not supply an isolated admission Store or application registrations.

Native execution records actual host, PID, creation time, working directory, command, input/model/runtime/source bytes and Store registration. Complete per-clip outputs are immutable. Resume needs the externally recorded terminal SHA, unchanged context and outputs, original-host exited-lifetime proof and matching terminal shared Store status. Scoring separately requires the sealed output index and its SHA plus its matching completed native terminal and SHA. A timeout is never process-exit evidence. Recursive consumer snapshots include the native vendor code. Torchvision initializes before threaded PyAV and the existing native FFmpeg logging restoration is preserved.

Raw archives, labels, videos, predictions and runtime receipts remain ignored. No consumed holdout-63 artifacts are used. Mirror authenticity, dataset usage rights, original identities/overlaps and live-scene/label validity remain unresolved. These diagnostics cannot establish complete serves, rally boundaries, identities, stroke families, forehand/backhand labels, doubles or unseen full-match correctness. No application truth or model is promoted.

The initial code passes 32 focused regressions and the full suite of 1,445 tests, with four existing optional GPU skips. Ruff, formatting of 163 files, dependency consistency and CLI checks pass. Tests caught and corrected two schema assumptions before native work: preserved native frame references are full clock records, and missing-label ordinals are lists. Generated CPU stubs exercise actual Store admission, live-worker fences and failure-before-completion without model inference. A real variable-rate source checks the temporary clock projection and preservation of application registrations. Consumer-copy races, foreign output directories/hosts, PID reuse, unbound resume history, changed source clocks, unavailable outputs and terminal/index mismatches are covered.
