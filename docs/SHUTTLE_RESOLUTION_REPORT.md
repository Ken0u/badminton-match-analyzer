# Fixed TrackNet resolution development comparison

Owning task: [issue 141](https://github.com/Ken0u/badminton-match-analyzer/issues/141), under [localization milestone 65](https://github.com/Ken0u/badminton-match-analyzer/issues/65). Implementation checkpoint, October 20, 2026: **no native comparison has run yet**. This report will retain the frozen protocol, actual compatibility result and both variants' results, including an incompatible or negative result. It does not claim improved annotation accuracy.

The [source-only visibility audit](SHUTTLE_VISIBILITY_REPORT.md) found ten visible misses with no observed component at the unchanged 0.5 threshold. Its wrong-location true shuttle was also absent from the component list. Re-ranking existing components cannot recover these missing components. This experiment compares exactly 512x288 and 768x432 with the same TrackNet checkpoint and threshold; application defaults remain 512x288. No weights are trained, downloaded or installed.

The [public protocol](../data/manifests/shuttle_resolution_protocol_v1.json) preserves all 60 familiar development cases, including 28 unknowns and missing/unavailable outputs. These are agent-assessed source labels, not human-certified or held-out truth. There is no established occlusion or camera-transition support, and this comparison cannot certify broader singles/doubles or unseen full-match correctness.

The portable runner is `scripts/compare_shuttle_resolution.py`. Its `freeze` command verifies the original source/label/native-cache graph and seals the protocol, all consumer source files, installed runtime versions, GPU/driver inventory and complete native target views. Use a new ignored output lineage and timestamp the resulting experiment hash on the issue before predictions. `run --variant control` uses every original frame in each complete target camera/background view, including median background samples, overlapping ensemble windows and selector ancestry. `run --variant candidate` refuses to start unless every control row reproduces the original frame/PTS/camera/point/component/context structure; only confidence has a predeclared absolute tolerance of 0.00001. A mismatch preserves diagnostics and blocks candidate inference and comparable scoring.

Pin `BADMINTON_ROOT` to the original input root, `BADMINTON_DATA_DIR` to its real `data/processed` shared Store and `BADMINTON_WEIGHTS_DIR` to the original `models/weights` **before imports**. The inference clock/cache path remains the separate frozen native baseline input; it never supplies job admission. Heavy work uses the actual shared `run_local_job` admission plus the queue's GPU grant. The runner records PID lifetime, working directory, command and Store job before importing inference libraries. Complete per-view checkpoints are exclusive and sealed; resume requires verification that each original process lifetime exited and its corresponding shared Store registration remains. A timeout is never exit evidence. Existing data, original predictions, annotations and weights remain unchanged.

Receipts and completed-view checkpoints publish atomically after a flushed, durable write, without replacing an existing destination. A generated interruption during a checkpoint write reproduced a truncated published file; the repair preserves incomplete pending files while exposing only a complete checkpoint, so a new attempt can proceed without overwriting previous evidence.

`report` verifies inputs/code/output seals again and reports visibility and localization separately, wrong-location FP+FN, radial coordinate uncertainty, observed-component recall and complete per-source/state/difficulty/disagreement/availability/selection denominators. Missing candidate views stay unavailable rather than disappearing or turning into negative labels. Zero-support groups have undefined metrics. Native elapsed time and peak GPU tensor allocation use the producer's seconds and decimal MB (10^6 bytes). Raw source media, labels, weights, model outputs and receipts remain ignored; only reproducible code/protocol and aggregate evidence belong in the repository.
